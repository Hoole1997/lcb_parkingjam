# 《挪车救援队》游戏内界面规范 V3

> 状态：实现基线  
> 更新日期：2026-07-29  
> 视觉基准：[parking_game_ui_v3.png](./art_direction/parking_game_ui_v3.png)

本文只覆盖游戏内界面表现，不修改《核心玩法策略 V2》的颜色订单、有限临停车位、无限阻挡尝试和通关规则。

## 1. 信息层级

游戏页从上到下只保留：

1. 金币、关卡号和暂停；
2. 无文字的当前订单小车位；
3. 无外框主棋盘；
4. 无标题、无比例、无父容器的独立临停车位。

不再显示剩余车辆、安全值、碰撞次数、当前/后续订单文字、颜色名称、`1/2`、停车位占用比例和常驻满位提示。

## 2. 主棋盘

- 手机左右只留 4–6 dp，棋盘尽量使用可用宽度。
- 沥青纹理直接结束于棋盘边缘，不绘制米色/绿色外框、路缘、围栏或阴影卡片。
- 只绘制内部格线，不绘制道路或出口箭头。
- 车辆不叠加方向箭头、三角形或其他车顶标记；方向由车头、前灯、挡风玻璃及车身朝向表达。
- 格子始终保持 1:1，复杂关卡通过缩小统一格子尺寸适配，禁止横纵拉伸。

## 3. 订单与临停车位

- 当前订单用目标色小车位数量表达：已完成为实心，未完成为空心。
- 订单图标只出现在棋盘上方，保留 TalkBack 的颜色和数量描述，不显示可见文字。
- 底部只显示全部临停车位；每个车位独立绘制，容量 2–5 时保持一行居中。
- 未来容量超过 5 时最多五列并换行，不能横向滚动或隐藏车位。
- 满位拒绝仍使用车辆回弹和一次性反馈，不增加常驻数据面板。

## 4. 自适应计算

```text
reservedHeight = HUD + 订单图标 + 临停车位 + 区块间距
cellSize = min(可用棋盘宽度 / columns, 剩余高度 / rows, 平板最大格子)
boardWidth = cellSize × columns
boardHeight = cellSize × rows
```

- `320×568dp`、`8×10`：目标格子 39 dp，棋盘约 `312×390dp`。
- `335×752dp`、`8×10`：棋盘宽度至少 327 dp。
- 竖屏平板：内容最大宽度 600 dp，格子最大 75 dp。
- 暂停热区始终不小于 48 dp。

## 5. 实现边界

- 效果图只用于视觉验收，不作为整屏运行时位图。
- Compose 绘制 HUD、订单图标和临停车位；`ParkingBoardView` 只负责棋盘、车辆、命中和动画。
- 领域层继续作为颜色、订单、停车容量和通关结果的唯一真相源。
- 棋盘 Canvas 不读取或推导订单；Compose 不执行车辆配对和容量判定。
